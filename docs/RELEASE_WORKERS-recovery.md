# Final-review worker recovery fixes

These changes address FG-01/FG-02 from the independent final review. Historical live-run artifacts, including `RELEASE_WORKERS-source.json` and `ASTRA_FINAL_GATE-repro.*`, remain unchanged. New source identities and local validation are recorded separately in `RELEASE_WORKERS-recovery-validation.json`.

On restart, an approved local file is independently rehashed against the fresh authoritative manifest and immutable policy. An intact copy stays Ready and is served without fetching the original source; a previously failed import with intact bytes can recover. Missing or corrupt content starts a bounded single-flight background import, with exponential retry delays capped at five minutes. Source failure cannot prevent HTTP startup or the separate settlement loop. Fixed credits and elapsed obligations remain content-independent. A successful recovery stops automatic import retries rather than continuously rehashing idle archives.

Unknown/Broadcasting journal entries first look up their existing transaction hash. Only an explicit `UNKNOWN_TRANSACTION` response permits replay, and only automatic workers or an explicitly executed operator command enable it. Replay uses exactly the durable signed bytes, hash and nonce. Persisted exponential pacing starts at five seconds and caps at ten minutes; there is no lifetime-attempt cutoff that would permanently strand a never-accepted transaction. Provider failures, non-final results and expired-byte errors remain Unknown, blocking replacement signatures. Restart cannot reset the replay pacing. Already finalized lost-response transactions reconcile without replay.

Read-only operator `--status` retains lookup-only behavior and never sends `send_tx`. A Prepared intent that was never marked for dispatch can be retired after fresh state establishes that it is no longer eligible; its journal identity remains available for inspection. Broadcasting and Unknown intents are never retired on an eligibility check or timeout. A FINAL result must identify the stored transaction hash, actual signer and bound contract receiver and contain a terminal execution status before the journal advances.

Validation: 18 targeted recovery/adapter tests passed; full JavaScript suite **75 passed, 0 failed, 0 skipped**; strict TypeScript passed. Tests cover crash-before-send replay, concurrent reconciliation, same-byte replay after more than five failures, durable pacing across restart, lookup failures, non-final and mismatched FINAL outcomes, no resend after lost-response final execution, read-only status, retirement of never-dispatched stale ownership intent, retained/fresh/corrupt copies with offline source and continued fixed-credit settlement.

The shipped `keeper/testnet-main.ts` is also launched as an actual child process after stopping its real local content source. It serves the original retained file byte-for-byte and automatically signs a fixed-credit claim through an explicitly mocked chain transport. This is an actual process/source-offline regression, not a new live-chain payment claim. No public chain write or original QA data mutation was performed for these fixes. The earlier genuine final-artifact automatic-worker receipts remain historical evidence for the previous source identities.
