# Operations and recovery

`node scripts/dev.mjs` runs API, Vite and two separate keeper processes. Ctrl-C stops the owned development processes. Preserve `data/app`, `data/keeper-a` and `data/keeper-b` across restarts. Never start two writers against the same keeper directory or point both keepers at one serving directory. Backend/keeper startup validates stored mode/identity bindings.

API configuration: `ARCHIVEPASS_API_PORT`, `ARCHIVEPASS_DATA_DIR`, `ARCHIVEPASS_OPERATOR_TOKEN`, `ARCHIVEPASS_WEB_ORIGIN`, `ARCHIVEPASS_MODE`, `ARCHIVEPASS_KEEPER_ORIGINS`. Default mode is local. Token defaults to a generated file under the application data directory. Testnet RPC failures never become local transaction successes. The read-only chain snapshot uses the fixed testnet deployment in `docs/testnet-config.json`.

Keeper standalone example:

```powershell
node keeper/main.ts --id a --port 8791 --data-dir data/keeper-a --provider keeper-a.archivepass.testnet --api-origin http://127.0.0.1:8788 --mode local
```

Use the matching shared local operator token. KeeperB uses idb/port8792/directorykeeper-b/providerkeeper-b. `ARCHIVEPASS_KEEPER_POLL_MS` defaults2000. Import a known asset explicitly via the UI or authenticated `POST /operator/import {asset_id}`. An import checks complete bytes, canonical manifest and root before becoming Ready. Unknown URLs/filesystem paths cannot be imported. Worker keys and mode cannot be chosen by browser actor strings onchain; automatic signed testnet workers and owner commands are implemented separately. Follow docs/RELEASE_WORKERS.md for the fixed binding, explicit signer, durable transaction journal and real automatic proof/payment evidence. The local role selector never chooses a blockchain signer.

Use the guarded shipped backup/restore commands in docs/RELEASE_OPERATIONS.md. Back up SQLite and referenced blob directories together. For this prototype, stop owned processes first, copy each entire data directory to a distinct backup, then restart. A copied SQLite database without blobs is not a content backup. WAL/shm files must be handled consistently; do not copy only the main database while writes are active. No background reset/cleanup deletes user uploads. Interrupted uploads are not publishable drafts; orphan cleanup requires an explicit narrow operator action after inspecting referenced blobs.

At restart the app checks ledger conservation. Payments have durable outbox/delivery records. Recovery reads the recorded result: success settles once, failure restores the same fixed credit, unknown remains pending. A timeout cannot reset or repay a claim. Retry after an actual failure uses a new attempt generation. Corrupt or missing keeper bytes prevent proving; re-import from the configured source after investigating, never synthesize success. Missed offline windows stay missed.

Local development faults require `ARCHIVEPASS_DEV_FAULTS=1`. Payment outcomes and keeper worker/serving controls are visibly simulated operational test tools. Disable faults for normal review. `scripts/scenario.mjs` needs them and restores keeper controls in a finally block. An actually disabled keeper returns an HTTP error and submits no proof; no contract payment is based on that HTTP observation.

Testnet scripts use only `.secrets` generated by ArchivePass. Never add user wallets. Provision actor balances for **maximum prepaid gas**, not only expected consumed gas. `testnet-bootstrap.mjs demo-root|fixture-root` generates and saves each dedicated key before faucet requests; rerun after a timeout to check the same account. `testnet-prepare.mjs` creates actors and immutable content metadata. Deploying a keyless account is irreversible by design; use faucet funds and verify source/tests/artifacts first. No sole user recovery key is deleted.

After interrupted signed transactions, inspect full saved outcomes, current commitment state and credits before continuing. Do not rerun an immutable initial workflow blindly. Final receipt status and balance changes matter; decoded function values alone are not transaction evidence. Unresolved callbacks remain pending. The prototype has no administrative owner override, beneficiary redirection or timeout rescue.

For a new timed deployment, use a fresh checkout without prior `.secrets`/runtime data, bootstrap both dedicated roots, then `node scripts/testnet-prepare.mjs --fresh`. This archives bundled public evidence under `docs/history` and provisions actor maximum-gas buffers before deployment. Preparation refuses a root that already has its immutable archive account. Preserve current evidence and credentials in this working checkout; the expired demonstration cannot be reset. Preparation uses the second faucet root to help fund operations/actor gas, not sponsorship principal. Then build/deploy and start the scenario promptly, because the immutable service windows use real chain time. The scenario preflights actor gas balances before accepting upkeep.
