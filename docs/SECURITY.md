# Security and trust boundaries

This is a hackathon prototype, not an audit or production service. The application operator controls the local demo ledger and actor selector. The local operator token restricts accidental browser access to the loopback service; it is not internet-ready identity authentication. The browser never receives NEAR signing keys.

The actual contract uses immediate predecessor/current NFT ownership, immutable content/policy, fixed provider/payee/deadline snapshots, a reserve/credit/pending ledger and private attempt-specific callbacks. Owner actions cannot withdraw upkeep. Transfer-call locks future provider configuration and service proposals until its resolver finishes, including when the receiver forwards the NFT. Existing provider actions and fixed claims remain usable. A resolver failure can leave future owner controls locked; there is no discretionary unlock.

The deployed asset's empty access-key list is checked separately from code behavior. Dedicated caretaker/provider/test receiver accounts retain prototype keys. Their keys confer account-specific authority, not access to the keyless asset balance. A keyless immutable contract cannot be repaired by an upgrade if a bug is later found. Operations funds are non-withdrawable and separate from restricted principal; significant faucet NEAR is provisioned for future bounded state. This is not an economic guarantee of cheap permanent storage.

Provider accounts/caps/refund beneficiary/expiry are fixed at initialization. An eligible provider can still cooperate with a caretaker, answer from another host, or supply sampled bytes without providing general HTTP availability. Challenges use runtime entropy with explicit predictability/opening-time limitations. No slashing, proof of replication, permanent storage, uptime oracle or independent-operator guarantee exists. Browser download observations do not authorize payments.

Uploads are public opaque bytes, bounded1byte..16MiB, never extracted/executed. Download responses are attachments with octet-stream/nosniff. Names never choose a filesystem path. IDs and indexes resolve through known persisted records/canonical roots. Keeper ingestion uses one configured API origin, rejects redirects and verifies actual full bytes before importing. No arbitrary URL fetcher is exposed. Treat downloaded content as untrusted even when its hash matches.

Local monetary mutation rechecks authoritative state inside SQLite transactions after asynchronous proof hashing. Integer amounts/times use BigInt/checked Rustu128/u64, serialized as decimal strings. UUID idempotency is scoped and body-bound; duplicate calls cannot earn twice. Unknown delivery cannot be reset from elapsed time. Finite providers/commitments/pending limits and measured storage headroom bound onchain state; complete history remains offchain in logs/exports.

The focused independent source review found two nonblocking keeper bugs: failed-payment retry reused an old idempotency key, and valid manifests were compared by JSON insertion order. Both were fixed with actual HTTP regressions. No blocking fund-loss or authority defect was identified by that review; this is not a formal proof or independent audit.
